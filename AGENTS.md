# AGENTS.md — herdr-tui (`hct`) Contributor & Agent Guidelines

## 1. Project Overview & Mission

`herdr-tui` (`hct`) is an open-source, lightweight multi-tab Terminal User Interface (TUI) client for [`herdr-core` (`hc`)](https://github.com/herdrdev/herdr-core), licensed under Apache-2.0.

### Architectural Invariants
1. **No Pane Splitting Complexity**: `hct` intentionally omits pane splitting and complex 2D tiling. Every tab displays a single full-size terminal viewport (with `^b o` available to cycle panes if a tab created by the desktop app contains multiple panes).
2. **Top `Space / Tab1 / Tab2 / [+]` Bar + Optional Dual Floating `+` Cross Pads (`--touch`) + Read-Only Bottom Agent Status Bar**:
   - **Top Tab Bar (`[ ⏏ ] [ ▾ Space ] ╱ [ 1:tab1 ] [ 2:tab2 ] [ + ] ... [ ? ]`)**: Occupies 1 compact row along the top edge (matching the 1-row Bottom Quota Status Bar). In Normal mode, all chrome (top bar, bottom quota bar, modals, floating crosses, and VT selection) renders with transparent (`Color::Reset`) backgrounds and line/underline/ANSI semantic styling—highlighting EVERY active tab (including `Working` / `Blocked` / `Done`) with `fg(Color::Reset) + Modifier::BOLD` + a state-colored bottom highlight underline (`Red` `Blocked`, `Yellow` `Working`, `Green` `Done`, `Cyan` `Idle`/`None`; no background pill fill) while inactive tabs carry their state foreground directly, keeping the bottom bar 100% transparent when idle, omitting `Modifier::BOLD` on chromatic ANSI 1..6 colors for `bold_is_bright` compatibility on light terminals, and dynamically adapting whenever the host terminal switches themes (expecting a theme-appropriate ANSI 16 palette and SGR 2 `DIM` support for muted hierarchy, while active tabs remain separated by `BOLD` + underline and quota tracks by `░` stipple glyphs even when `DIM` is ignored). On Agent tabs (delegating via `is_active_tab_agent` to `TerminalInfo::is_agent()`, which checks `herdr-core`'s native OSC 7501 active `status` first, then `foreground.name`/`foreground.argv` including script-wrapped entrypoints while ignoring window `title`, tab `name`, `template`, and post-exit `turn > 0`), Normal mode also italicizes intermediate AI process rows by default (thoughts including `▸ Thought`, tool calls, `└ Tip:` sub-step hints, spinners, and collapsed action summaries such as `… N more actions …`, excluding fenced code blocks and numbered code lines), dropping `Modifier::BOLD` and adding `Modifier::DIM` on non-muted cells while preserving VT colors (`fg`/`bg`) and existing SGR 2 `DIM`, whereas plain shell tabs stay untouched. In `-e` / `--eink` mode, chrome uses paper-white `#FFFFFF` paper with active-tab highlight underline and Carta 4-bit neutral quantization, and process rows (including collapsed action summaries, excluding fenced code blocks) render in `#777777` italic. Agent states are color-coded without redundant circle prefixes. Tapping `[ ⏏ ]` on the far left detaches `hct` while keeping sessions running (`^b q` / `Action::Detach`). Tapping `[ ▾ Space ]` (or pressing `^b b`) opens a secondary floating Space Switcher popover (`Modal::SpaceMenu`) with 2-row Space cards and a `[ + New Space ]` button. Tapping any Tab pill switches directly to that Tab; when many tabs are open, inactive tabs fold via Accordion mode (`[ 1 ] [ 2 ] [ 3:active ] [ 4 ]`) so tabs stay in fixed order without scrolling, falling back to clickable `[ ‹N ]` / `[ N› ]` hidden-count badges (which open `Modal::Fuzzy`) on extreme tab counts; tapping `[ + ]` immediately after the rightmost Tab creates a new Tab in the active Space; tapping `[ ? ]` opens the Quick Actions & Help panel. The Left Sidebar is removed so the terminal viewport always spans 100% of the screen width.
   - **Dual Floating Draggable Semi-Transparent `+` Cross Pads (`hct --touch`)**: When `--touch` (or `ui.touch_mode = true`) is enabled, renders two `15 × 7` hollow-corner `+` cross overlays over the terminal viewport (hidden by default when running `hct` without `--touch`):
     - **Left Modifier Cross (`Esc` / `Ctl` / `^B` / `Alt` / `Tab`)**: Top = `Esc`, Left = sticky `Ctl`, Center = sticky `^B` prefix, Right = sticky `Alt`, Bottom = `Tab`.
     - **Right Directional & Paste Cross (`↑` / `←` / `⎘` / `→` / `↓`)**: Top = `↑`, Left = `←`, Center = `⎘` Paste, Right = `→`, Bottom = `↓`.
     - Both `+` crosses have 4 completely hollow corners (100% transparent to underlying terminal text and mouse events), keep width-1 underlying VT glyphs dimmed (`Modifier::DIM`) inside non-glyph arm cells, and use disjoint Normal-mode hues (`Magenta` idle border → `Cyan` dragging border, `Green` arrows/paste/active modifiers) while shifting freely anywhere within the terminal viewport.
   - **Bottom 1-Row Read-Only Focused-Agent Quota Status Bar**: Strictly 1 row, displaying **only** the currently focused agent's remaining quota via strictly local-only reads with zero external API calls or credential/keyring access (`Codex` 5h/7d rate limits from local session JSONL snapshots, `Antigravity` 5h/daily step quota from local transcript logs, `OpenCode` daily/5h local SQLite stats, `Claude` 5h/7d local JSONL stats, `Freebuff` local session quota JSON) as 8-step Unicode fractional block progress bars combined with remaining percentage (`██████▋░ 83%`), omitting redundant status/CWD/turn info already shown by the agent's own TUI, plus `[ ✓ Copied ]` and clickable `[ ▼ BOT (+N) ]` when scrolled up. When E-Ink mode (`hct -e` / `--eink` / `^b e`) is active, left (`‹`) and right (`›`) vertically-centered see-through edge tabs render along the viewport edges using linear tab stepping (`‹` clamps at Tab 1 and exits `Modal::TabOverview` back to the last tab; `›` steps past the last tab into trailing `Modal::TabOverview`), while page scrolling uses `Shift+PgUp` (or `PgUp`/`PgDn` in scrollback), `^b PgUp`/`^b PgDn`, or `[ ? ]`.
   - **Built-In `Modal::Reader` (`^b v` / `[ 📖 Reader ]`)**: `^b v` (or `[ 📖 Reader ]` in `[ ? ]`) opens a full-screen embedded Reader (`src/reader.rs`) occupying the entire terminal `area` (hiding the outer top/bottom bars behind crisp top and bottom frame hairlines) sourced from `herdr-core`'s `terminal.read` RPC with offline VT screen fallback; Agent tabs default to Clean mode (stripping trailing prompt/footer chrome, collapsing intermediate AI thought/tool/action-summary rows via `is_plain_text_process_row`, retaining <= 3 turns, anchoring on the latest response) and format dividers across 3 semantic tiers (`ReaderDividerKind::{Major, Section, Collapsed}`: `═` turn/command boundaries, `─` in-content Markdown horizontal rules, `┄` collapsed process lines, merging adjacent dividers with `Major > Section > Collapsed` precedence), with `[ Full ]`/`[ Clean ]` (`c`/`f`/`Tab`), refresh (`r`), `[ Latest ]` (`l`), and pagination (`PgUp`/`PgDn`/`Space`/`b`/`^b PgUp`/`^b PgDn`/wheel/touch drag). Both Normal (`Color::Reset` bg, chromatic unbolded accents) and E-Ink (Carta 4-bit neutral LUT, zero `DIM`) invariants apply.
   - **Touch Text Selection & OSC 52 Clipboard**: Dragging inside the terminal viewport highlights text and automatically copies the selection to the client clipboard on release via OSC 52.
   - **Outer Session Reporting (`OSC 1337;SetUserVar`)**: `OuterSessionReporter` exposes `herdr_session` (effective trimmed `--session` / `$HC_SESSION` forwarded identically via `connect_session_arg` to `CoreClient::connect_with_sender`, or `""` when unset) and focused `herdr_terminal` (`world.active_terminal_address_ref()`, or `""` when empty) to outer terminals via standard Base64-encoded `OSC 1337;SetUserVar` sequences (with `tmux` — requiring `allow-passthrough on` — and `screen` DCS passthrough via `detect_multiplexer_env` and `format_single_osc_sequence`), deduplicated outside `BeginSynchronizedUpdate`/`EndSynchronizedUpdate` right after terminal sync and cleared on exit and `TerminalCleanupGuard::drop`.
3. **Bidirectional `doc("herdr-app")` Sync**:
   - Reads and writes `herdr-core`'s `doc("herdr-app")` layout document with CAS version checks (`doc.get` / `doc.set`).
   - Preserves unknown JSON fields (`#[serde(flatten)]`) so official Herdr Desktop and Android clients never lose metadata when `hct` saves changes.
   - Shares attention state via `herdr.seen=<turn>` terminal labels.
4. **Privacy & No Personal Data**:
   - Never commit machine hostnames, usernames, home paths, IP addresses, or personal emails in code, tests, comments, or documentation.

## 2. Build & Test Commands

```bash
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test
cargo build --release
```

## 3. Issue, Branch & PR Workflow

- Every feature or bugfix starts from a tracked GitHub Issue (`issue-<N>`).
- Develop on branch `feat/issue-<N>` (or `fix/issue-<N>`).
- Run `cargo test` and `cargo clippy` before pushing.
- Open a Pull Request referencing `Fixes #<N>` and request `@codex review`.
- Do not push implementation code directly to `main` or merge without review approval.
